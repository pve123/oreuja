# 방구석 등반대 (MVP)

브라우저에서 산과 등산 코스를 골라 걸어 올라가는 웹 3D 앱이다. 지금은 북한산(코스 4개)과 도봉산(코스 3개), 관악산(코스 2개), 수락산(코스 3개)이 있고, 산을 하나씩 더해 갈 예정이다. 정상에 닿으면 머리 위에 「⛰️🚩 정상이다」가 뜨고 인증 배지를 받으며, 그 말풍선이 들어간 기념사진을 저장할 수 있다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

| 입력 | 동작 |
|---|---|
| `↑` | 보고 있는 쪽으로 걷기. 지형 위를 자유롭게 걷는다. 나무 줄기·바위·건물은 지나가지 못하고 둘레를 따라 미끄러진다. 등산로에서 12m를 넘으면 바깥쪽 걸음이 느려지고 화면 가장자리가 어두워지며, 20m에서 더 나가지 못한다 |
| `←`/`→` | 몸 돌리기. `↑` 와 같이 누르면 걸으면서 돈다. 카메라는 늘 등 뒤로 따라 돈다 |
| `↓` | 뒤로 물러나기 |
| `Shift` | 빨리 걷기 |
| `Space` | 점프 (걸으면서 누르면 앞으로 나아가며 뛴다) |
| 마우스 끌기 | 캐릭터 둘레로 카메라를 돌려 둘러본다(정면 보기). 다시 걷거나 몸을 돌리면 등 뒤로 돌아간다 |
| 마우스 휠 | 확대·축소 (4~15m). 처음에는 7m 에서 시작한다 |
| 베이스캠프 | 첫 화면이 걷히면 출발점에서 내 캐릭터를 앞에서 비추는 장면 위에 뜬다. 산 탭, 코스 카드(거리·오르막·예상 시간·고도 그래프·완등 횟수와 최고 기록·지금 오르는 사람 수), 산 탭(오른 코스 수), 조작 방식(쉬운 조작·자유 조작), 하늘(지금·새벽·낮·노을·밤), 캐릭터를 고르고 「출발」(`Enter`)을 누른다. 고른 것은 브라우저에 기억해서 다시 오면 「출발」만 누르면 된다 |
| `Esc` 또는 코스 패널의 「산·코스 바꾸기」 | 걷는 중에 베이스캠프를 다시 연다. 오르던 코스면 「이어서 오르기」와 「처음부터」를 고른다. 다른 코스를 고르면 처음부터 오르고, 다른 산을 고르면 그 산의 지형을 받으러 다시 불러온 뒤 바로 출발한다 |
| `1`~`7` 또는 왼쪽 아래 감정 표현 버튼 | 안녕하세요 👋, 감사합니다 🙏, 야호 📣, 만세 🙌, 정상이다 ⛰️🚩, 힘내세요 💪, 파이팅 🔥. 그림과 말이 내 머리 위와 같은 코스 사람들 화면에 3초 동안 뜬다 |
| 왼쪽 아래 닉네임 ✎ | 닉네임 바꾸기 (12자까지, 브라우저에 기억). 처음에는 「쉬엄쉬엄 김밥 담당」처럼 산악회 느낌의 이름을 무작위로 붙인다 |
| 화면 왼쪽 아래 스피커 버튼 | 소리 켜기·끄기. 소리는 첫 키나 클릭 뒤에 나온다 |
| 화면 오른쪽 위 캐릭터 그림 | 아바타 바꾸기. 도형으로 만든 병맛 캐릭터 5종(기본 등산객, 형광 아저씨, 감자, 오리, 두부)과 GLB 캐릭터 6종(꼬마 수염 아저씨, 꼬마 등산객, 꼬마 개구쟁이, 곰탈 전사, 숲지기, 갑옷 기사). 고른 캐릭터는 브라우저에 기억한다 |
| 「걷기」 버튼 | 쉬운 조작에서 누르면 등산로를 따라 저절로 걷고 다시 누르면 멈춘다. 폰은 왼쪽 아래, 컴퓨터는 미니맵 위에 있다. 방향키를 누르면 저절로 걷기를 멈춘다 |
| 화면 왼쪽 아래 조이스틱 | 자유 조작의 터치 화면에서 엄지를 댄 자리에 생긴다. 좌우로 기울이면 몸을 돌리고 위로 밀면 걷는다. 조금 기울이면 천천히 걷고 끝까지 밀면 뛰며 아래로 당기면 뒷걸음친다 |
| 화면 오른쪽 빈 곳 끌기, 두 손가락 벌리기 | 터치 화면에서 둘러보기와 확대·축소 |
| 화면 오른쪽 아래 「점프」 버튼 | 터치 화면에서 점프 |
| 코스·캐릭터·도움말 패널의 ⌄ | 패널 접기·펼치기. 접은 상태는 브라우저에 기억한다. 컴퓨터에서는 처음에 코스와 캐릭터 패널을 펼쳐 두고, 터치 화면에서는 코스 패널을 접어 두고 캐릭터와 도움말은 숨긴다 |

개발 모드에서는 주소에 값을 붙여 원하는 지점부터 확인할 수 있다. `?course=bukhansan-sanseong` 을 붙이면 베이스캠프를 건너뛰고 그 코스로(다른 산이면 `?mountain=dobongsan` 도 붙인다), `?d=1700` 을 붙이면 출발점에서 1700m 떨어진 곳에서 시작하고, `?d=1790&photo` 를 붙이면 정상에 도착하자마자 기념사진까지 자동으로 찍는다. `?time=05:40` 이나 `?time=12-21T17:30` 을 붙이면 그 시각의 하늘로 고정한다.

## 시험

PR 과 main 에 올라가면 GitHub Actions(`.github/workflows/ci.yml`)가 시험을 돌린다.

| 시험 | 명령 | 걸리는 시간 | 하는 일 |
|---|---|---|---|
| 린트·빌드 | `npm run lint`, `npm run build` | 1분 안 | 코드 검사와 타입 검사 |
| 코스 점검 | `npm run test:courses` | 몇 초 | 코스 파일만 보고 출발 방향이 거꾸로인지, 지나온 자리로 되짚어 오는지, 출발 직후나 중간에 크게 내려갔다 오르는지, 이정표 순서와 도착점 높이가 맞는지 본다 |
| 화면 시험 | `npm run build && npm run test:e2e` | 맥 1분, GitHub 10분 안팎 | 헤드리스 크롬으로 걷기, 코스 바꾸기, 폰 쉬운 조작, 감정 표현, 삼성 인터넷처럼 hover 를 알리는 폰, 정상 기념사진을 눌러 본다 |

화면 시험은 설치된 크롬을 쓴다(`CHROME_PATH` 로 위치를 바꾼다). GitHub 시험 컴퓨터에는 그래픽 카드가 없어 3D 를 CPU(SwiftShader)로 그리므로 느리다. 맥에서 같은 조건으로 보려면 `E2E_GL=swiftshader` 를 붙이고, `E2E_ONLY=걷기` 처럼 주면 이름에 그 글이 든 시험만 돈다. 실패하면 `tests/screenshots` 에 화면을 남기고 GitHub 에서는 내려받을 수 있게 올린다.

코스 점검은 OSM 원본(`scripts/raw`, 저장소에서 뺌) 없이 도는 규칙만 쓴다. 그래서 진달래능선처럼 이름과 다른 길로 가는 코스는 못 잡으니, 코스를 새로 만들 때는 OSM 원본으로 정식 등산로 비율을 따로 본다.

## 같이하기 (선택)

같이하기 서버를 켜면 같은 코스를 오르는 다른 사람의 아바타와 닉네임이 보인다. 개발 서버에서 같이하기 서버가 꺼져 있으면 혼자 오르기로 동작하고 5초마다 다시 붙어 본다. 배포본은 `VITE_MULTIPLAYER_URL` 이 비어 있으면 아예 붙어 보지 않는다. 혼자/같이 고르기는 같이하기를 열 때 다시 만든다. 서버는 지금도 `hidden` 으로 알린 사람을 남의 화면에 그리지 않으니, 「혼자」를 고르면 `hidden` 을 보내게 하면 된다. 베이스캠프에 있는 사람(`lobby`)도 산길에는 그리지 않는다.

```bash
npm run server   # 같이하기 서버 (ws://localhost:5200)
npm run dev      # 다른 터미널에서. 개발 서버가 /ws 를 같이하기 서버로 넘겨준다
```

- 같은 PC에서는 브라우저 창을 여러 개 열어 확인한다.
- 같은 와이파이의 다른 기기로 확인하려면 `npm run dev -- --host` 로 켜고 화면에 나온 네트워크 주소로 접속한다.
- 밖에서 친구와 하려면 같이하기 서버를 올릴 곳(Render, Fly.io 등)이 필요하다. 올린 뒤 `.env.local` 의 `VITE_MULTIPLAYER_URL` 에 `wss://` 주소를 넣는다.

서버(`server/index.mjs`)는 닉네임, 아바타, 코스, 등산로 위 거리와 옆으로 비킨 거리, 감정 표현만 주고받고 아무것도 저장하지 않는다. 메시지 크기(512바이트)와 빈도(초당 30개), 접속 수(50명)를 제한하고, 받은 값은 범위를 잘라 쓴다. 로그인이 없어서 닉네임은 누구나 아무렇게나 정할 수 있다.

밖에 올릴 때를 위해 다음도 막는다. `npm run test:server` 가 빈 포트에 서버를 따로 띄워 이 동작을 시험한다(CI 의 check 에서도 돈다).

- 접속 출처: 브라우저가 붙이는 Origin 이 배포 주소(`ALLOWED_ORIGINS`, 기본 `https://trailverse-seven.vercel.app`), Vercel 미리보기 주소(`trailverse-…-hsl-labs.vercel.app`), localhost 일 때만 받는다.
- 같은 브라우저: 창을 여러 개 열어도 마지막 창 하나만 붙는다. 이전 창에는 「다른 창에서 같이하는 중」과 「이 창에서」 버튼이 뜬다.
- 같은 IP 접속 수: 여섯까지. 집·학교처럼 IP 하나를 나눠 쓰는 경우를 생각했다. 내 컴퓨터(localhost)에서 온 접속은 개발 중 창을 여러 개 띄울 수 있게 뺀다.
- 끊긴 연결: 15초마다 ping 을 보내 답이 없으면 끊는다. 폰이 잠들거나 와이파이가 끊긴 사람이 남의 화면에 남지 않는다.
- 상태 확인: `GET /health` 가 `{ ok, players }` 를 돌려준다. 호스팅 서비스의 상태 확인 주소로 쓴다.

| 서버 환경변수 | 뜻 |
|---|---|
| `PORT` | 듣는 포트. 호스팅 서비스가 정해 주면 그 값을 쓴다 (기본 5200) |
| `ALLOWED_ORIGINS` | 접속을 받을 페이지 주소, 쉼표로 여럿. 배포 주소를 바꾸면 여기에 넣는다 |
| `TRUST_PROXY` | `1` 이면 `X-Forwarded-For` 첫 주소를 접속한 사람 IP 로 본다. 호스팅 프록시 뒤에 둘 때(Railway, Fly.io, Render 모두 그렇다) 반드시 켠다. 안 켜면 모두가 프록시 IP 하나로 보여 전체가 여섯 명으로 막히고, 서버가 경고를 남긴다. 프록시 없이 켜면 누구나 머리글을 꾸며 IP 제한을 피한다 |

## 위성사진 (선택)

`.env.example` 을 `.env.local` 로 복사하고 브이월드 인증키를 넣으면 지형에 항공사진(브이월드 영상지도)을 입힌다. 인증키가 없거나 타일을 받지 못하면 고도와 경사로 칠한 색을 쓴다. Vite는 서버를 켤 때 이 파일을 읽으니 바꾼 뒤에는 `npm run dev` 를 다시 실행한다.

```bash
cp .env.example .env.local   # VITE_VWORLD_KEY=... 를 채운다
```

인증키는 [브이월드](https://www.vworld.kr)에 가입해 「인증키 발급」에서 받는다. 활용 API 는 WMTS/TMS API 와 배경지도 API 를 고르고, 서비스 URL 에 쓸 주소를 넣는다. 인증키는 빌드 결과에 들어가는 공개 키지만 등록한 주소에서만 통한다. 운영 주소(`https://www.oreuja.com`)와 개발 주소(`http://localhost:5173`)를 한 키에 넣지 못하면 키를 둘 받아 `.env.local` 과 Vercel 에 따로 넣는다. PR 미리보기 주소는 등록하지 않았으니 위성사진 없이 나온다.

타일은 WMTS(`api.vworld.kr/req/wmts/1.0.0/{키}/Satellite/{확대}/{행}/{열}.jpeg`, 256px)로 받아 화면을 열 때마다 이어 붙이기만 하고 따로 저장하지 않는다. 인증키가 틀리거나 등록하지 않은 주소면 브이월드는 그림 대신 오류 XML 을 돌려준다. 받은 타일의 20% 넘게 실패하면 그 사진은 쓰지 않는다. 위성사진을 쓰면 화면 오른쪽 아래에 브이월드 출처를 표시한다.

## Vercel 에 올리기

정적 파일만 올리는 배포라 혼자 오르기만 된다. Vercel 에는 웹소켓 서버를 둘 수 없어서 `VITE_MULTIPLAYER_URL` 을 비워 두면 배포본은 같이하기 서버를 찾지 않고 베이스캠프의 「같이」 아래에 「서버 없음」이 보인다.

1. Vercel 대시보드에서 「Add New Project」를 누르고 GitHub 의 `pve123/trailverse` 저장소를 고른다. `vercel.json` 이 Vite 프리셋과 `npm run build`, `dist` 를 알려 주니 빌드 설정은 그대로 둔다.
2. Environment Variables 에 `VITE_VWORLD_KEY`(운영 주소를 등록한 브이월드 인증키)와 `SITE_URL`(`https://www.oreuja.com`, 미리보기 카드의 주소)을 Production 으로 넣는다. 인증키를 비우면 위성사진 없이 고도 색으로 지형을 그린다.
3. 「Deploy」를 누른다. 이후에는 main 에 올라갈 때마다 자동으로 다시 배포하고 PR 브랜치는 미리보기 주소를 받는다.

같이하기까지 열려면 `server/index.mjs` 를 Railway·Fly.io·Render 같은 곳에 올리고(시작 명령 `npm run server`, 상태 확인 `/health`, 환경변수 `TRUST_PROXY=1`) Vercel 환경변수 `VITE_MULTIPLAYER_URL` 에 `wss://` 주소를 넣은 뒤 다시 배포한다. 환경변수는 빌드할 때 들어가므로 넣은 뒤 꼭 다시 배포해야 한다.

링크를 카카오톡이나 슬랙에 붙였을 때 보이는 미리보기 그림은 `public/og-image.jpg`(1200x630)다. og:image 는 절대 주소여야 해서 빌드할 때 `vite.config.ts` 의 `socialMeta` 가 넣는다. Vercel 이 빌드 중에 알려 주는 운영 주소(`VERCEL_PROJECT_PRODUCTION_URL`)를 쓰고, 다른 주소를 쓰려면 Vercel 환경변수 `SITE_URL` 에 `https://` 로 시작하는 주소를 넣는다. 로컬 빌드에는 넣지 않는다.

미리보기가 실제로 뜨려면 메신저 서버가 로그인 없이 페이지와 그림을 받아 갈 수 있어야 한다. Vercel 프로젝트의 Settings 에서 Deployment Protection 의 Vercel Authentication 이 켜져 있으면 모든 주소가 Vercel 로그인 화면으로 넘어가서 미리보기도 뜨지 않는다. 누구나 들어와 쓰게 하려면 운영 주소에서는 이 보호를 끈다.

## 스마트폰

폰 브라우저의 「홈 화면에 추가」로 설치하면 주소창 없이 앱처럼 열린다(`public/manifest.webmanifest`, `index.html` 의 apple 메타, 아이콘 `public/icon-*.png` 와 `apple-touch-icon.png`). 아이콘 원본은 `public/favicon.svg` 다.

화면은 노치와 홈바까지 쓰고(`viewport-fit=cover`) 고정 패널은 `env(safe-area-inset-*)` 만큼 비킨다.

조작은 베이스캠프에서 두 가지 가운데 고르고 브라우저에 기억한다. 폰은 쉬운 조작, 컴퓨터는 자유 조작이 기본이다. 쉬운 조작은 어르신이나 아이, 3D 게임이 낯선 사람을 위한 방식이다. 조이스틱 대신 큰 「걷기」 버튼 하나를 누르면 캐릭터가 등산로 5m 앞을 향해 몸을 돌리며 저절로 걷고, 다시 누르면 멈춘다. 길에서 비켜나 있어도 그 지점을 보고 걸어 길 가운데로 돌아온다. 걷는 동안 손가락으로 둘러보면 손을 뗀 뒤 2.5초 지나 카메라가 다시 등 뒤로 돌아온다. 베이스캠프를 열거나 정상에 닿으면 저절로 걷기를 멈춘다.

자유 조작은 요즘 모바일 3D 게임 방식이다. 왼쪽 아래 빈 곳에 엄지를 대면 그 자리에 조이스틱이 생긴다. 좌우로 기울이면 몸을 돌리고 위로 밀면 걸어서 카메라는 늘 등 뒤에서 가는 쪽을 본다. 조금 기울이면 천천히 걷고 끝까지 밀면 뛴다. 오른쪽 빈 곳은 끌어서 둘러보고 두 손가락으로 확대·축소하며, 오른쪽 아래 버튼으로 뛴다(`src/ui/TouchControls.tsx`, `src/scene/World.tsx`). 점프 버튼 위 💬 를 누르면 감정 표현 일곱 가지가 펼쳐진다(`src/ui/EmoteDial.tsx`). 둘러보기는 손가락 1px 에 도는 각도를 화면 높이와 상관없이 같게 맞춰 세로 폰 너비만큼 끌면 약 60° 돌고 손가락을 떼면 잠깐 미끄러지다 멈춘다. 조이스틱 좌우와 둘러보기에는 제곱 반응 곡선을 넣었다. 조이스틱을 조금 기울이거나 손가락을 천천히 끌면 세밀하게 돌고, 끝까지 밀거나 휙 쓸면 크게 돈다. 좁은 화면에서는 캐릭터 패널과 닉네임 패널을 숨기고 진행 패널을 코스 패널 아래로 올려 아래쪽을 조작 자리로 비운다.

처음 걸을 때는 조이스틱과 둘러보기와 점프 자리를 손가락 그림으로 짚어 주는 안내가 한 번 뜬다. 화면을 누르거나 8초가 지나면 사라지고 브라우저에 기억해 다시 띄우지 않는다(`src/ui/TouchControls.tsx` 의 `TouchGuide`). 걷는 동안에는 Screen Wake Lock API 로 화면이 저절로 꺼지지 않게 한다(`src/lib/wakeLock.ts`).

터치 기기(`src/lib/device.ts` 의 `IS_TOUCH`)는 그림자 지도를 절반으로 줄이고 앰비언트 오클루전과 멀티샘플링을 끈다. 화소 배율은 drei 의 `PerformanceMonitor` 로 기기에 맞춘다. 가장 높은 배율(폰 1.5배, 컴퓨터 2배)에서 시작해 초당 프레임이 40 아래로 떨어지면 0.25 씩 내리고(폰은 0.75배까지) 여유가 생기면 다시 올린다. 오르내림 방향이 네 번 바뀌면 배율을 바꿀 때마다 생기는 끊김을 피하려고 가장 낮은 배율에 둔다(`src/App.tsx`).

## 지형과 등산로 데이터

```bash
npm run data
```

원본 다운로드는 `scripts/raw/` 에 캐시하고 git에는 올리지 않는다. 이 폴더를 지우고 다시 실행하면 새로 받는다.

| 파일 | 내용 |
|---|---|
| `mountains.json` | 산 목록 (id, 이름, 가장 높은 봉우리 해발, 코스 수) |
| `<산 id>/terrain.bin` | 높이 값(북쪽 행부터). `terrain.json` 의 `encoding` 이 `uint16` 이면 minHeight~maxHeight 를 0~65535 로 나눠 담는다(한 칸 약 1.2cm) |
| `<산 id>/terrain.json` | 격자 크기와 로컬 좌표 범위 |
| `<산 id>/courses.json` | 코스별 등산로 점(로컬 미터 좌표), 길이, 누적 오르막, 이정표 |

산과 코스는 `scripts/prepare-data.mjs` 의 `MOUNTAINS` 에 적는다. 산마다 지형 한 장과 그 위의 코스들이 있다. `npm run data -- dobongsan` 처럼 산 id 를 주면 그 산만 다시 만든다.

### 도봉산

정상 자운봉(740m)은 암벽 장비가 있어야 올라서, 등산객이 오르는 바로 옆 신선대(726m)를 정상으로 삼는다.

| 코스 | 난이도 | 출발 → 도착 | 거리 | 누적 오르막 |
|---|---|---|---|---|
| 신선대 코스 | 보통 | 도봉산탐방지원센터 → 신선대 | 3.17km | 709m |
| 망월사 코스 | 어려움 | 원도봉탐방지원센터 → 신선대 | 3.98km | 827m |
| 우이암 코스 | 쉬움 | 무수골 매표소 → 우이암 | 2.15km | 446m |

### 관악산

사당 코스는 사당역에서 1km 가까이 도시 길을 지나야 해서 등산로가 시작되는 관음사에서 출발한다. 관악문에서 연주대로 오르는 마지막 바위 구간(계단과 난간이 있다)은 OSM 에 암벽으로 올라 있는데, 빼면 연주암 쪽으로 85m 를 내려갔다 돌아 올라서 이 코스만 짧은 암벽 구간을 허용한다(코스의 `allowAlpine`).

| 코스 | 난이도 | 출발 → 도착 | 거리 | 누적 오르막 |
|---|---|---|---|---|
| 사당 코스 | 보통 | 관음사 → 연주대 | 4.02km | 701m |
| 과천 코스 | 보통 | 과천향교 → 연주대 | 3.49km | 669m |

### 수락산

국립공원이 아니라 탐방지원센터가 없어서 등산로 입구의 광장·절을 출발점으로 삼는다. 장암 코스는 석림사 계곡에서 능선으로 올라 기차바위를 거쳐 주봉에 닿는다. 석림사·용굴암·도솔봉은 OSM 지점이 등산로에서 40m 넘게 떨어져 있어서 이정표마다 허용 거리를 70m 로 늘렸다(이정표의 `maxOffset`).

| 코스 | 난이도 | 출발 → 도착 | 거리 | 누적 오르막 |
|---|---|---|---|---|
| 수락산역 코스 | 보통 | 수락산광장 → 주봉 | 3.14km | 693m |
| 장암 코스 | 어려움 | 석림사 입구 → 주봉 | 2.87km | 607m |
| 도솔봉 코스 | 보통 | 학림사 → 주봉 | 2.70km | 518m |

등산로를 찾을 때는 출입금지(`access=no`) 구간과 비법정탐방로, 암벽 구간을 빼고 정식 등산로를 먼저 고른다. 코스에 `allowAlpine` 을 주면 암벽 구간도 쓰되 비용을 3배로 매겨 돌아가는 길보다 훨씬 짧을 때만 지난다. 길이 도착점 5m 안을 지나 그 너머 노드까지 갔다 되돌아오면 도착점에서 끝낸다. 북한산성 계곡길 일부는 OpenStreetMap에 차도(`residential`)로 올라 있어서 작은 차도도 함께 받는다. 출발점은 도착 지점과 이어진 길 가운데 가장 가까운 점으로 잡는다. 가장 짧은 길이 대표 코스가 아니면 코스의 `via` 에 반드시 거쳐 갈 지점을 적는다(도봉산 신선대 코스의 마당바위, 망월사 코스의 망월사와 포대능선, 북한산 진달래능선 코스의 능선 위 두 곳, 관악산 사당 코스의 하마바위와 마당바위, 관악문, 수락산 장암 코스의 기차바위). 이정표 좌표는 OpenStreetMap의 같은 이름 지점에서 가져오고, 등산로에서 40m 안에 있을 때만 쓴다(이정표에 `maxOffset` 을 주면 그 거리까지).

## 정밀 지형 (선택)

국토지리정보원 1:5,000 수치지형도의 등고선(5m 간격)과 표고점으로 7.5m 간격 지형을 만든다. DXF 파일을 `scripts/raw/ngii/` 에 넣고 `npm run data` 를 실행한다. 산마다 `MOUNTAINS` 의 `sheets` 에 적은 도엽 번호가 파일 이름에 든 DXF 만 쓴다. 파일이 없으면 AWS Terrain Tiles(30m 원본)만 쓴다.

1. 국토정보플랫폼(map.ngii.go.kr) 자료실 → 지도자료 → 수치지도 탭에서 1:5,000 수치지형도를 DXF로 신청해 받는다. 지역은 시도와 시군구로 고른다(도봉산은 서울특별시 도봉구, 경기도 의정부시·양주시).
   - 북한산: `37608039`, `37608040`, `37608049`, `37608050`
   - 도봉산: `37705011`, `37705012`, `37705021`, `37705022`, `37705031`, `37705032`, `37608020`, `37608030`, `37608040`(북한산과 같이 씀)
   - 관악산: `37612018`, `37612019`, `37612020`, `37612028`, `37612029`, `37612030` (서울특별시 관악구, 경기도 과천시)
   - 수락산: `37705013`, `37705014`, `37705023`, `37705024` (서울특별시 노원구, 경기도 의정부시)
2. 받은 DXF를 `scripts/raw/ngii/` 에 복사한다. 파일 이름에 도엽 번호만 들어 있으면 된다.
3. `npm run data` 를 실행한다.

스크립트(`scripts/contour-dem.mjs`)는 GDAL 없이 동작한다.

- DXF에서 주곡선(`F0017111`), 계곡선(`F0017114`), 표고점(`F0027217`) 레이어를 읽는다.
- 좌표계 EPSG:5186(중부원점 TM)을 위경도로 바꾼다.
- 등고선이 지나는 칸에 높이를 찍고, 나머지 칸은 라플라스 보간으로 채운다.
- 도엽 밖은 30m 원본을 쓴다. 30m 원본은 표고점과 비교한 높이 기준 차이(지금 1.0m)만큼 올려 경계가 튀지 않게 한다.

`public/data/<산 id>/terrain.bin` 은 이 데이터로 만든 결과물이다. 신청할 때 사용 목적은 「교육, 학습, 연구」로 했다. 레포를 공개하거나 서비스로 운영하려면 국토지리정보원 이용 조건을 다시 확인한다.

## GLB 캐릭터

Kenney Mini Characters 3종과 KayKit Adventurers 3종을 쓴다. 둘 다 CC0 1.0 이다. 캐릭터를 바꾸거나 더하려면 두 팩을 받아 압축을 풀고 스크립트에 폴더를 넘긴다.

```bash
node scripts/prepare-avatars.mjs ~/Downloads/kenney_mini-characters ~/Downloads/KayKit_Adventurers_2.0_FREE
```

- 받는 곳: https://kenney.nl/assets/mini-characters , https://kaylousberg.itch.io/kaykit-adventurers
- 쓸 캐릭터는 스크립트 위쪽 `KENNEY`·`KAYKIT` 목록에, 화면 이름과 동작 이름은 `src/lib/avatars.ts` 의 `AVATARS`·`AVATAR_MODELS` 에 적는다. 같이하기 서버(`server/index.mjs`)의 `AVATARS` 에도 더해야 다른 사람에게 보인다.
- Kenney 캐릭터는 동작이 파일 안에 들어 있다. KayKit 은 동작이 따로 있어서, 스크립트가 쓰는 동작(`Idle_A`, `Walking_A`, `Jump_Idle`, `Jump_Full_Short`)만 골라 메시를 뺀 `animations.glb`(약 160KB)로 합친다. 원본 두 파일은 마네킹 메시까지 들어 있어 1.5MB 가 넘는다.

### 모델 압축 (meshopt)

캐릭터와 나무 GLB 는 meshopt 로 압축해 넣는다. 13개 합계가 4.3MB 에서 1.8MB 로 줄었다. 브라우저에서 푸는 기능은 drei `useGLTF` 에 들어 있다. 압축하면 좌표를 정수로 담으므로, 모양을 월드 좌표로 굽는 곳은 `src/lib/geometry.ts` 의 `bakeGeometry` 로 실수로 푼 뒤 옮긴다. 모델을 새로 넣거나 `prepare-avatars` 를 다시 돌렸으면 아래처럼 다시 압축한다. Kenney 캐릭터는 압축할 때 텍스처(`Textures/colormap.png`)가 GLB 안에 들어가므로, 압축한 뒤 `public/models/avatars/kenney/Textures/` 는 지운다.

```bash
npx @gltf-transform/cli meshopt public/models/trees/Pine_2.glb public/models/trees/Pine_2.glb
```
