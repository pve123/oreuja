# 방구석 등반대 (MVP)

브라우저에서 산과 등산 코스를 골라 걸어 올라가는 웹 3D 앱이다. 지금은 북한산(코스 4개)과 도봉산(코스 3개)이 있고, 산을 하나씩 더해 갈 예정이다. 정상에 닿으면 인증 배지를 받고 기념사진을 저장할 수 있다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

| 입력 | 동작 |
|---|---|
| `↑` | 보고 있는 쪽으로 걷기. 지형 위를 자유롭게 걷는다. 나무 줄기·바위·건물은 지나가지 못하고 둘레를 따라 미끄러진다. 등산로에서 12m를 넘으면 바깥쪽 걸음이 느려지고 화면 가장자리가 어두워지며, 20m에서 더 나가지 못한다 |
| `←`/`→` | 몸 돌리기. `↑` 와 같이 누르면 걸으면서 돈다. 카메라는 늘 등 뒤로 따라 돈다 |
| `↓` | 뒤로 물러나기 |
| `Shift` | 빨리 걷기 |
| `Space` | 점프 (걸으면서 누르면 앞으로 나아가며 뛴다) |
| 마우스 끌기 | 캐릭터 둘레로 카메라를 돌려 둘러본다(정면 보기). 다시 걷거나 몸을 돌리면 등 뒤로 돌아간다 |
| 마우스 휠 | 확대·축소 (4~15m). 처음에는 7m 에서 시작한다 |
| 코스 패널의 「산·코스 바꾸기」 | 산과 코스 고르기. 고른 산과 코스는 브라우저에 기억한다. 코스를 바꾸면 처음부터 다시 오르고, 산을 바꾸면 그 산의 지형을 받으러 첫 화면부터 다시 연다 |
| `1` `2` `3` 또는 왼쪽 아래 👋 🙌 ❤️ 버튼 | 감정 표현. 내 머리 위와 같은 코스 사람들 화면에 3초 동안 뜬다 |
| 왼쪽 아래 닉네임 ✎ | 닉네임 바꾸기 (12자까지, 브라우저에 기억) |
| 화면 왼쪽 아래 스피커 버튼 | 소리 켜기·끄기. 소리는 첫 키나 클릭 뒤에 나온다 |
| 화면 오른쪽 위 캐릭터 그림 | 아바타 바꾸기. 도형으로 만든 병맛 캐릭터 5종(기본 등산객, 형광 아저씨, 감자, 오리, 두부)과 GLB 캐릭터 6종(꼬마 수염 아저씨, 꼬마 등산객, 꼬마 개구쟁이, 곰탈 전사, 숲지기, 갑옷 기사). 고른 캐릭터는 브라우저에 기억한다 |
| 화면 오른쪽 아래 「걷기」 버튼 | 터치 화면에서 누르고 있는 동안 걷기 |
| 화면 오른쪽 아래 「점프」 버튼 | 터치 화면에서 점프 |
| 화면 왼쪽 아래 ◀ ▶ 버튼 | 터치 화면에서 몸 돌리기 |
| 코스·캐릭터·도움말 패널의 ⌄ | 패널 접기·펼치기. 접은 상태는 브라우저에 기억한다. 좁은 화면에서는 처음에 코스 패널을 접어 두고 도움말은 숨긴다 |

개발 모드에서는 주소에 값을 붙여 원하는 지점부터 확인할 수 있다. `?course=bukhansan-sanseong` 을 붙이면 그 코스로, `?d=1700` 을 붙이면 출발점에서 1700m 떨어진 곳에서 시작하고, `?d=1790&photo` 를 붙이면 정상에 도착하자마자 기념사진까지 자동으로 찍는다.

## 같이하기 (선택)

같이하기 서버를 켜면 같은 코스를 오르는 다른 사람의 아바타와 닉네임이 보인다. 서버가 없으면 혼자 오르기로 동작하고 5초마다 다시 붙어 본다.

```bash
npm run server   # 같이하기 서버 (ws://localhost:5200)
npm run dev      # 다른 터미널에서. 개발 서버가 /ws 를 같이하기 서버로 넘겨준다
```

- 같은 PC에서는 브라우저 창을 여러 개 열어 확인한다.
- 같은 와이파이의 다른 기기로 확인하려면 `npm run dev -- --host` 로 켜고 화면에 나온 네트워크 주소로 접속한다.
- 밖에서 친구와 하려면 같이하기 서버를 올릴 곳(Render, Fly.io 등)이 필요하다. 올린 뒤 `.env.local` 의 `VITE_MULTIPLAYER_URL` 에 `wss://` 주소를 넣는다.

서버(`server/index.mjs`)는 닉네임, 아바타, 코스, 등산로 위 거리와 옆으로 비킨 거리, 감정 표현만 주고받고 아무것도 저장하지 않는다. 메시지 크기(512바이트)와 빈도(초당 30개), 접속 수(50명)를 제한하고, 받은 값은 범위를 잘라 쓴다. 로그인이 없어서 닉네임은 누구나 아무렇게나 정할 수 있다.

## 위성사진 (선택)

`.env.example` 을 `.env.local` 로 복사하고 Mapbox 공개 토큰(`pk.` 로 시작)을 넣으면 지형에 위성사진을 입힌다. 토큰이 없거나 타일을 받지 못하면 고도와 경사로 칠한 색을 쓴다. Vite는 서버를 켤 때 이 파일을 읽으니 바꾼 뒤에는 `npm run dev` 를 다시 실행한다.

```bash
cp .env.example .env.local   # VITE_MAPBOX_TOKEN=pk.... 를 채운다
```

토큰은 빌드 결과에 들어가는 공개 토큰이라, Mapbox 계정 화면에서 쓸 주소(URL)를 제한해 둔다. 위성 타일은 Static Tiles API(`mapbox/satellite-v9` 스타일)로 받는다. 새 계정에서는 v4 Raster Tiles API가 `429` 로 막혀 있었다. 위성사진을 쓰면 화면 오른쪽 아래에 Mapbox와 Maxar 출처를 표시해야 한다.

## 지형과 등산로 데이터

```bash
npm run data
```

원본 다운로드는 `scripts/raw/` 에 캐시하고 git에는 올리지 않는다. 이 폴더를 지우고 다시 실행하면 새로 받는다.

| 파일 | 내용 |
|---|---|
| `mountains.json` | 산 목록 (id, 이름, 가장 높은 봉우리 해발, 코스 수) |
| `<산 id>/terrain.bin` | 높이 값(북쪽 행부터). `terrain.json` 의 `encoding` 이 `uint16` 이면 minHeight~maxHeight 를 0~65535 로 나눠 담는다(한 칸 약 1.2cm) |
| `<산 id>/terrain.json` | 격자 크기와 로컬 좌표 범위 |
| `<산 id>/courses.json` | 코스별 등산로 점(로컬 미터 좌표), 길이, 누적 오르막, 이정표 |

산과 코스는 `scripts/prepare-data.mjs` 의 `MOUNTAINS` 에 적는다. 산마다 지형 한 장과 그 위의 코스들이 있다. `npm run data -- dobongsan` 처럼 산 id 를 주면 그 산만 다시 만든다.

### 북한산

| 코스 | 난이도 | 출발 → 도착 | 거리 | 누적 오르막 |
|---|---|---|---|---|
| 백운대 코스 | 보통 | 백운대탐방지원센터 → 백운대 | 2.08km | 573m |
| 북한산성 코스 | 어려움 | 북한산성탐방지원센터 → 백운대 | 3.77km | 839m |
| 진달래능선 코스 | 보통 | 아카데미탐방지원센터 → 대동문 | 1.89km | 426m |
| 영봉 코스 | 쉬움 | 백운대탐방지원센터 → 영봉 | 1.01km | 298m |

### 도봉산

정상 자운봉(740m)은 암벽 장비가 있어야 올라서, 등산객이 오르는 바로 옆 신선대(726m)를 정상으로 삼는다.

| 코스 | 난이도 | 출발 → 도착 | 거리 | 누적 오르막 |
|---|---|---|---|---|
| 신선대 코스 | 보통 | 도봉산탐방지원센터 → 신선대 | 3.17km | 709m |
| 망월사 코스 | 어려움 | 원도봉탐방지원센터 → 신선대 | 3.67km | 845m |
| 우이암 코스 | 쉬움 | 우이탐방지원센터 → 우이암 | 1.98km | 458m |

등산로를 찾을 때는 출입금지(`access=no`) 구간과 비법정탐방로, 암벽 구간을 빼고 정식 등산로를 먼저 고른다. 북한산성 계곡길 일부는 OpenStreetMap에 차도(`residential`)로 올라 있어서 작은 차도도 함께 받는다. 출발점은 도착 지점과 이어진 길 가운데 가장 가까운 점으로 잡는다. 가장 짧은 길이 대표 코스가 아니면 코스의 `via` 에 반드시 거쳐 갈 지점을 적는다(도봉산 신선대 코스의 마당바위, 망월사 코스의 망월사와 포대능선). 이정표 좌표는 OpenStreetMap의 같은 이름 지점에서 가져오고, 등산로에서 40m 안에 있을 때만 쓴다.

## 정밀 지형 (선택)

국토지리정보원 1:5,000 수치지형도의 등고선(5m 간격)과 표고점으로 7.5m 간격 지형을 만든다. DXF 파일을 `scripts/raw/ngii/` 에 넣고 `npm run data` 를 실행한다. 산마다 `MOUNTAINS` 의 `sheets` 에 적은 도엽 번호가 파일 이름에 든 DXF 만 쓴다. 파일이 없으면 AWS Terrain Tiles(30m 원본)만 쓴다.

1. 국토정보플랫폼(map.ngii.go.kr) 자료실 → 지도자료 → 수치지도 탭에서 1:5,000 수치지형도를 DXF로 신청해 받는다. 지역은 시도와 시군구로 고른다(도봉산은 서울특별시 도봉구, 경기도 의정부시·양주시).
   - 북한산: `37608039`, `37608040`, `37608049`, `37608050`
   - 도봉산: `37705011`, `37705012`, `37705021`, `37705022`, `37705031`, `37705032`, `37608020`, `37608030`, `37608040`(북한산과 같이 씀)
2. 받은 DXF를 `scripts/raw/ngii/` 에 복사한다. 파일 이름에 도엽 번호만 들어 있으면 된다.
3. `npm run data` 를 실행한다.

스크립트(`scripts/contour-dem.mjs`)는 GDAL 없이 동작한다.

- DXF에서 주곡선(`F0017111`), 계곡선(`F0017114`), 표고점(`F0027217`) 레이어를 읽는다.
- 좌표계 EPSG:5186(중부원점 TM)을 위경도로 바꾼다.
- 등고선이 지나는 칸에 높이를 찍고, 나머지 칸은 라플라스 보간으로 채운다.
- 도엽 밖은 30m 원본을 쓴다. 30m 원본은 표고점과 비교한 높이 기준 차이(지금 1.0m)만큼 올려 경계가 튀지 않게 한다.

`public/data/<산 id>/terrain.bin` 은 이 데이터로 만든 결과물이다. 신청할 때 사용 목적은 「교육, 학습, 연구」로 했다. 레포를 공개하거나 서비스로 운영하려면 국토지리정보원 이용 조건을 다시 확인한다.

## GLB 캐릭터

Kenney Mini Characters 3종과 KayKit Adventurers 3종을 쓴다. 둘 다 CC0 1.0 이다. 캐릭터를 바꾸거나 더하려면 두 팩을 받아 압축을 풀고 스크립트에 폴더를 넘긴다.

```bash
node scripts/prepare-avatars.mjs ~/Downloads/kenney_mini-characters ~/Downloads/KayKit_Adventurers_2.0_FREE
```

- 받는 곳: https://kenney.nl/assets/mini-characters , https://kaylousberg.itch.io/kaykit-adventurers
- 쓸 캐릭터는 스크립트 위쪽 `KENNEY`·`KAYKIT` 목록에, 화면 이름과 동작 이름은 `src/lib/avatars.ts` 의 `AVATARS`·`AVATAR_MODELS` 에 적는다. 같이하기 서버(`server/index.mjs`)의 `AVATARS` 에도 더해야 다른 사람에게 보인다.
- Kenney 캐릭터는 동작이 파일 안에 들어 있다. KayKit 은 동작이 따로 있어서, 스크립트가 쓰는 동작(`Idle_A`, `Walking_A`, `Jump_Idle`, `Jump_Full_Short`)만 골라 메시를 뺀 `animations.glb`(약 160KB)로 합친다. 원본 두 파일은 마네킹 메시까지 들어 있어 1.5MB 가 넘는다.

### 모델 압축 (meshopt)

캐릭터와 나무 GLB 는 meshopt 로 압축해 넣는다. 13개 합계가 4.3MB 에서 1.8MB 로 줄었다. 브라우저에서 푸는 기능은 drei `useGLTF` 에 들어 있다. 압축하면 좌표를 정수로 담으므로, 모양을 월드 좌표로 굽는 곳은 `src/lib/geometry.ts` 의 `bakeGeometry` 로 실수로 푼 뒤 옮긴다. 모델을 새로 넣거나 `prepare-avatars` 를 다시 돌렸으면 아래처럼 다시 압축한다.

```bash
npx @gltf-transform/cli meshopt public/models/trees/Pine_2.glb public/models/trees/Pine_2.glb
```
