# 북한산 등산 메타버스 (MVP)

브라우저에서 북한산 등산 코스를 골라 걸어 올라가는 웹 3D 앱이다. 정상에 닿으면 인증 배지를 받고 기념사진을 저장할 수 있다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

| 입력 | 동작 |
|---|---|
| `W` 또는 `↑` | 앞으로 걷기 |
| `S` 또는 `↓` | 뒤로 걷기 |
| `A`/`D` 또는 `←`/`→` | 옆으로 걷기. 등산로에서 30m 넘게 멀어지면 등산로 위로 순간이동한다 |
| `Shift` | 빨리 걷기 |
| `Space` | 점프 (걸으면서 누르면 앞으로 나아가며 뛴다) |
| `Q`/`E` | 시점 회전 |
| 마우스 휠 | 확대·축소. 시점은 걸을 때 캐릭터 뒤로 자동으로 돌아가고, Q/E 로 돌린 뒤 2초간은 그대로 둔다 |
| 화면 오른쪽 위 캐릭터 그림 | 아바타 바꾸기 (기본 등산객, 형광 아저씨, 감자, 오리, 두부). 고른 캐릭터는 브라우저에 기억한다 |
| 화면 오른쪽 아래 「걷기」 버튼 | 터치 화면에서 누르고 있는 동안 걷기 |
| 화면 오른쪽 아래 「점프」 버튼 | 터치 화면에서 점프 |
| 화면 왼쪽 아래 ◀ ▶ 버튼 | 터치 화면에서 옆으로 걷기 |

개발 모드에서는 주소에 값을 붙여 원하는 지점부터 확인할 수 있다. `?d=1700` 을 붙이면 출발점에서 1700m 떨어진 곳에서 시작하고, `?d=1790&photo` 를 붙이면 정상에 도착하자마자 기념사진까지 자동으로 찍는다.

## 위성사진 (선택)

`.env.example` 을 `.env.local` 로 복사하고 Mapbox 공개 토큰(`pk.` 로 시작)을 넣으면 지형에 위성사진을 입힌다. 토큰이 없거나 타일을 받지 못하면 고도와 경사로 칠한 색을 쓴다. Vite는 서버를 켤 때 이 파일을 읽으니 바꾼 뒤에는 `npm run dev` 를 다시 실행한다.

```bash
cp .env.example .env.local   # VITE_MAPBOX_TOKEN=pk.... 를 채운다
```

토큰은 빌드 결과에 들어가는 공개 토큰이라, Mapbox 계정 화면에서 쓸 주소(URL)를 제한해 둔다. 위성 타일은 Static Tiles API(`mapbox/satellite-v9` 스타일)로 받는다. 새 계정에서는 v4 Raster Tiles API가 `429` 로 막혀 있었다. 위성사진을 쓰면 화면 오른쪽 아래에 Mapbox와 Maxar 출처를 표시해야 한다.

## 구성

| 영역 | 사용 기술 |
|---|---|
| 3D | Three.js, React Three Fiber, drei |
| 상태 | zustand (`src/lib/store.ts`) |
| 지형 | AWS Terrain Tiles(Terrarium, 약 30m 해상도)로 만든 `public/data/terrain.bin` |
| 등산로 | OpenStreetMap 데이터로 만든 `public/data/courses.json` |
| 기록 | 지금은 `localStorage` 에 저장하고, 다음 단계에서 Supabase로 옮긴다 |

| 파일 | 하는 일 |
|---|---|
| `scripts/prepare-data.mjs` | 지형과 등산로 데이터를 만든다 (`npm run data`) |
| `src/lib/data.ts` | 데이터를 불러오고, 등산로 위 위치와 실제 소요 시간을 계산한다 |
| `src/scene/World.tsx` | 이동, 카메라, 정상 판정, 사진 촬영을 맡는다 |
| `src/scene/Terrain.tsx` | 지형 메시를 고도와 경사에 따라 칠한다 |
| `src/scene/Forest.tsx` | 나무를 `InstancedMesh` 로 심는다 |
| `src/scene/Hiker.tsx` | 도형으로 만든 임시 아바타다. GLB 캐릭터로 바꿀 예정이다 |
| `src/ui/Hud.tsx` | 코스 정보, 진행률, 정상 배지와 사진 창을 그린다 |

## 지형과 등산로 데이터

```bash
npm run data
```

원본 다운로드는 `scripts/raw/` 에 캐시하고 git에는 올리지 않는다. 이 폴더를 지우고 다시 실행하면 새로 받는다.

| 파일 | 내용 |
|---|---|
| `terrain.bin` | 높이 값(Float32, 북쪽 행부터) |
| `terrain.json` | 격자 크기와 로컬 좌표 범위 |
| `courses.json` | 코스별 등산로 점(로컬 미터 좌표), 길이, 누적 오르막, 이정표 |

코스는 `scripts/prepare-data.mjs` 의 `COURSES` 에 적는다. 지형 한 장 위에 코스 네 개가 있다.

| 코스 | 난이도 | 출발 → 도착 | 거리 | 누적 오르막 |
|---|---|---|---|---|
| 백운대 코스 | 보통 | 백운대탐방지원센터 → 백운대 | 2.08km | 573m |
| 북한산성 코스 | 어려움 | 북한산성탐방지원센터 → 백운대 | 3.77km | 839m |
| 진달래능선 코스 | 보통 | 아카데미탐방지원센터 → 대동문 | 1.89km | 426m |
| 영봉 코스 | 쉬움 | 백운대탐방지원센터 → 영봉 | 1.01km | 298m |

등산로를 찾을 때는 출입금지(`access=no`) 구간과 비법정탐방로, 암벽 구간을 빼고 정식 등산로를 먼저 고른다. 북한산성 계곡길 일부는 OpenStreetMap에 차도(`residential`)로 올라 있어서 작은 차도도 함께 받는다. 출발점은 도착 지점과 이어진 길 가운데 가장 가까운 점으로 잡는다. 이정표 좌표는 OpenStreetMap의 같은 이름 지점에서 가져오고, 등산로에서 40m 안에 있을 때만 쓴다.

## 정밀 지형 (선택)

국토지리정보원 1:5,000 수치지형도의 등고선(5m 간격)과 표고점으로 7.5m 간격 지형을 만든다. DXF 파일을 `scripts/raw/ngii/` 에 넣고 `npm run data` 를 실행한다. 파일이 없으면 AWS Terrain Tiles(30m 원본)만 쓴다.

1. 국토정보플랫폼(map.ngii.go.kr) 자료실 → 지도자료 → 수치지도 탭에서 1:5,000 수치지형도를 DXF로 신청해 받는다. 지금은 네 코스가 모두 들어가는 `37608039`, `37608040`, `37608049`, `37608050` 네 장을 쓴다.
2. 받은 DXF를 `scripts/raw/ngii/` 에 복사한다. 파일 이름은 상관없다.
3. `npm run data` 를 실행한다.

스크립트(`scripts/contour-dem.mjs`)는 GDAL 없이 동작한다.

- DXF에서 주곡선(`F0017111`), 계곡선(`F0017114`), 표고점(`F0027217`) 레이어를 읽는다.
- 좌표계 EPSG:5186(중부원점 TM)을 위경도로 바꾼다.
- 등고선이 지나는 칸에 높이를 찍고, 나머지 칸은 라플라스 보간으로 채운다.
- 도엽 밖은 30m 원본을 쓴다. 30m 원본은 표고점과 비교한 높이 기준 차이(지금 1.0m)만큼 올려 경계가 튀지 않게 한다.

`public/data/terrain.bin` 은 이 데이터로 만든 결과물이다. 신청할 때 사용 목적은 「교육, 학습, 연구」로 했다. 레포를 공개하거나 서비스로 운영하려면 국토지리정보원 이용 조건을 다시 확인한다.
